## 三、两个按钮的最终决策

| | 复制这句 | 拿去练手 |
|---|---|---|
| 动作 | `setClipboardData`，留在语录页 | 存 `pendingQuote` → 跳拆招页 → `runAnalyze()` 自动分析 |
| 拿到 | 这一句原文，粘贴就发 | 意图分析 + 3 套新回话 |
| 门槛 | 零 | 强制登录、占一次分析额度 |
| 本质 | 终点：这句就是答案 | 起点：把这句当"对方说的话"再拆一遍 |

**决策：主按钮只留「复制这句」，卡片不再渲染「拿去练手」入口。**
理由：语录 `content` 是**我方回话**，拆招页输入框要的是**对方说的话**，语义错位；且强制登录 + 占额度，把用户从「找到答案」拉回「再加工」。

**链路代码完整保留**：`QuoteCardProps.onUse` 仍为可选、`quotes/index.tsx` 的 `handleUse` / `setPendingQuote` / `onUse={handleUse}` 全部原样保留，`defend/index.tsx` 的回填逻辑不动。若日后要恢复导流，只需在卡片里加一个渲染入口，改名「练练怎么接」更诚实。
