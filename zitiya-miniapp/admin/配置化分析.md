# 嘴替鸭 · 配置化分析

> 目的：梳理「已经能配置什么」「本次后台新增/改造了什么」「还能继续配置化什么」。
> 配套后台：`/admin`（零依赖 Node 服务 + 原生 JS 管理面板）。

---

## 一、已经存在的「管理接口」（本次接入后台前）

嘴替鸭的配置原本散落在 4 处，没有统一入口：

| 位置 | 形态 | 能配置的内容 | 痛点 |
| --- | --- | --- | --- |
| `src/services/sceneConfig.ts` | 小程序 LocalStorage（key `zuitiya_scene_config`） | 关键词覆盖、自定义意图、自定义语录、爬虫话题、提示词覆盖 | 只能改代码或手动改 Storage，无 UI |
| `scripts/config_cli.py` | 离线 CLI，编辑 Storage JSON | 同上（命令行增删改查） | 非技术人员用不了 |
| 云函数 `daily_crawler` | 云数据库 `scene_config`（`_id=main`） | 只认 `crawlTopics` / `keywordOverrides` | 改话题要去云控制台 |
| 云函数 `get_daily_quotes` | 云数据库 `daily_quotes` | 只读语录 | 无 |
| `DEFAULT_PROMPTS` | 代码常量（`sceneConfig.ts`） | analyze / quoteGen / rewrite 三个提示词，支持 `patch.prompts` 覆盖 | 覆盖入口没有，只能改源码 |

**结论**：配置能力其实早就有（patch 机制），但**缺少集中可视的后台**，且提示词/厂商/漏斗大量硬编码。

## 二、本次新增 / 改造（后台 + 小程序侧联动）

### 2.1 后台管理系统 `/admin`（新增）
- 零依赖 Node 服务（`server.js`，仅用内置模块），启动 `node server.js` → http://localhost:8787
- 默认值**直接提取小程序源码**（`intents.ts` / `quotes.ts` / `settings.ts` 的 `LLM_PRESETS` / `sceneConfig.ts` 的 `DEFAULT_PROMPTS` + `DEFAULT_CRAWL_TOPICS` / `attackScenes.ts` 的 `ATTACK_SCENES` + `ATTACK_CATEGORIES`），保证后台与小程序同源、不漂移
- patch 持久化到 `admin/data/scene_config.json`，schema 与 `zuitiya_scene_config` 完全一致
- 管理面板 10 个 Tab：**概览 / 意图 / 固定语录 / 爬虫话题 / 出招场景 / 模型厂商 / 提示词 / 漏斗参数 / 运行时参数 / 导入导出**
- 支持：查看 + 增删改 + 意图匹配模拟（`/api/check`）+ 导出（LocalStorage 形态 / 云数据库形态）+ 导入
- 修复了原 `config_cli` 与 `sceneConfig` 的合并语义，统一为一套 `model.js`

### 2.2 小程序侧改造（让后台配置真正生效，全部向后兼容）
| 改造点 | 文件 | 说明 |
| --- | --- | --- |
| 厂商预设可配置 | `sceneConfig.ts` 新增 `getLLMPresets()` / `getAsrPresets()`；`useAppStore.ts`、`settings/index.tsx` 改用它们 | 后台新增/覆盖的厂商预设，贴回 Storage 后设置页自动出现 |
| 漏斗参数可配置 | `sceneConfig.ts` 新增 `getFunnelConfig()` + `DEFAULT_FUNNEL_CONFIG`；`quoteFunnel.ts` 改用配置 | minScore / 各项打分加权，后台可调，无需改代码 |
| 提示词更全面 | `sceneConfig.ts` 的 `DEFAULT_PROMPTS` 新增 `quoteGenUser`、`rephraseUser` 两个可配置 user 模板；`quoteGenerator.ts`、`engine.ts` 改用模板 + 占位符替换 | LLM 的「生成语录」「换说法」user 提示词也能在后台改 |
| 出招场景库可配置 | `sceneConfig.ts` 新增 `getAttackScenes()` / `getAttackCategories()`（默认=源码 `ATTACK_SCENES`/`ATTACK_CATEGORIES`，patch 覆盖/新增）；`attack/index.tsx` 改用配置读取 | 后台「出招场景」Tab 可增删改场景（开场话术 + 谈话闭环）与分类，贴回 Storage 后出招页实时生效 |
| 模型参数可配置 | `sceneConfig.ts` 新增 `DEFAULT_MODEL_PARAMS` + `getModelParams(purpose)`（档位 default/analyze/quoteGen/rephrase/test）；`llm.ts` 全局兜底、`engine.ts` 拆招分析/换说法、`quoteGenerator.ts` 语录生成 均改读配置 | 温度/maxTokens/超时按调用用途分档，后台「运行时参数」Tab 可改，无需改代码 |
| 每日语录 TTL 可配置 | `sceneConfig.ts` 新增 `getDailyQuoteTTLMs()`；`quoteCache.ts` 缓存过期改读配置；云函数 `daily_crawler` 从 `scene_config.dailyQuoteTTLDays` 读 TTL 算清理窗口 | 前端缓存与云函数清理共用同一后台配置，后台「运行时参数」Tab 设天数即时生效 |
| 每日入库上限可配置 | `sceneConfig.ts` 新增 `getDailyQuoteLimit()`/`setDailyQuoteLimit()`（默认 100，1~500）；云函数 `daily_crawler` 从 `scene_config.dailyQuoteLimit` 读上限算 Top N 入库；`config_cli.py`/`backend` 已支持 | 后台「运行时参数」Tab 设条数即时生效，导出「云数据库文档」带此字段；「立即抓取一次」也会带上此值 |

> 所有改造在 patch 为空时行为与原版完全一致（默认值即原硬编码值），不影响现有用户。

## 四、数据流（一处修改，三端生效）

```
后台 /admin  ──改──>  admin/data/scene_config.json (patch)
                         │  导出
                         ├─> 小程序 LocalStorage zuitiya_scene_config  (设置页/引擎/漏斗 读)
                         └─> 云数据库 scene_config (_id=main)          (daily_crawler 读话题/关键词)
```

API Key 始终留在用户设备本地（`zuitiya_llm_settings`），后台只管理**公开配置**（厂商 baseURL/模型、提示词、意图、语录、话题、漏斗参数），不碰密钥。
