# 嘴替鸭 weapp 构建故障诊断与修复指引

> 记录时间：2026-11-13
> 触发问题：微信开发者工具报 `[ app.json 文件内容错误] dist/weapp/app.json ... app.json is not found`
> 结论：**代码与配置都没错，卡在构建环境（磁盘 100% 满）**。本轮沙箱内未能产出完整包，需按第 4 节在本地完成一次构建。

---

## 1. 现象

`dist/weapp/` 里 `app.json` / `app.js` / `app.wxss` 全部缺失，只剩 `project.config.json`（有时残留 `taro.js`/`vendors.js`/`pages/` 空壳）。模拟器因此找不到入口。

**微信开发者工具只认 `dist/weapp` 里的成品，不会自己编译 Taro 源码。** 每次改 `.tsx` / `.scss` 都必须重跑一次 Taro 构建；只要构建被打断，就会得到这个报错。

---

## 2. 逐层定位结果（本轮实测）

| 层次 | 结论 | 证据 |
|---|---|---|
| 配置 | ✅ 正确，**不要改** | `project.config.json` 的 `miniprogramRoot: "dist/weapp/"` 与 `config/index.ts` 的 `outputRoot: dist/${type}` 一致 |
| 代码 | ✅ 无语法/模块错误 | 全项目 62 个 TS/TSX 经 esbuild 语法自检 `bad=0`；`app.config.ts` 通过；webpack `851/851 dependencies` 全部 build 完并进入 sealing |
| 卡点一 | ❌ `CssMinimizerPlugin` 在 `sealing (92%) asset processing` **永久卡死** | 4 次构建停在同一位置，10–15 分钟零推进 |
| 卡点二 | ❌ 绕过压缩后报 `ModuleBuildError: write EPIPE` | 编译能在 4.06–4.20m 跑完，但 TaroMiniPlugin 写产物阶段失败；`>file` 重定向与 `tee\|tail` 管道两种写法**都复现** → 排除输出方式 |
| 环境根因 | ❌ **磁盘 100% 满，仅 1.2Gi 可用**；内存 free ~107MB | `df -h /System/Volumes/Data` = `438Gi used / 1.2Gi avail / 100%`；无残留 taro/webpack/sass 进程（已排除孤儿进程假说） |

**因果链**：磁盘接近 0 → webpack 写临时文件/emit 失败、子进程管道断裂（EPIPE）→ 产物写不出来；同时资源紧张导致进程被 SIGKILL/SIGTERM（多次 exit −1 / 137），CSS 压缩阶段尤其容易卡死。

---

## 3. 本轮做的唯一代码改动

`config/index.ts` 的 `mini.webpackChain` 增加应急开关（**默认完全不生效**，h5 段未动）：

```ts
// 应急开关：部分构建环境下 CssMinimizerPlugin 会在 sealing(92%) 阶段卡死，
// 显式设置 SKIP_MINIFY=1 时跳过压缩以产出未压缩包。默认行为完全不变。
if (process.env.SKIP_MINIFY === '1') {
  chain.optimization.minimize(false);
}
```

已验证：设了它以后，编译从「永久卡死」变成「4.2 分钟跑完」。默认构建、正式提审包行为一行未变。可保留，也可随时撤销。

## 5. 注意事项

- **别手工伪造 `app.json`**：缺 `app.js` / `app.wxss` / pages 的包照样起不来。
- **别改 `miniprogramRoot`**：改了只会越改越乱。
- `SKIP_MINIFY=1` 产出的是**未压缩包**，仅用于预览/真机自测；**正式提审包请用默认构建**（带压缩）。
- 项目 `config/index.ts` 里 `cache.enable: false`，每次都是全量编译（约 4–8 分钟），属正常。
- 本轮及此前几批改动（拆招页改版、语录页改版、隐私协议、各方案与清单文档）**全部尚未 git commit**，且工作区叠着「积分/调用次数限制」并行线的未提交改动，提交前需先划定范围。

## 7. 2026-11-14 复测结论（语录页 v2 改版后，用户说「好了你跑吧」）

| 项 | 结果 |
|---|---|
| 复测磁盘 | **仍 367–386Mi / 100%**，空间并未实际释放 |
| Time Machine 本地快照 | `tmutil listlocalsnapshots /` 为空 → 排除快照占用 |
| swap | `vm.swapusage total 3328M / used 2850M / free 477M`，内存压力极大 |
| 构建 | `SKIP_MINIFY=1` 后台 7m53s，日志仅 4 行（Taro 启动 + punycode 警告），**webpack 阶段根本没启动**；`app.json` 被清、`dist/weapp` 剩 7 文件 |
| 兜底 | 开工前备份 56 文件，失败后完整恢复：`app.json` / `app.js` / `app.wxss` + `pages/quotes` 四件套齐全，模拟器可起（但仍是 v1 包） |

**阈值结论（重要，别再白试）**：11-13 有 1.2Gi 时 `SKIP_MINIFY=1` 至少能跑完编译 4.2 分钟（只是写盘 EPIPE）；现在 <400Mi 时连 webpack 都起不来。**可用空间不足 1GB 时不必再试构建**，先腾空间，目标 ≥10GB。

**为什么磁盘满会让 webpack 连启动都做不到**：内存 free 极低、swap 已用 2.85G/3.33G，macOS 需要磁盘空间扩展 swap 文件；盘满 → swap 无法扩展 → Node 分配内存失败 → 进程静默挂起（日志零输出，不是压缩卡死）。所以除腾磁盘外，**先退出微信开发者工具**也能明显降压（它常驻多个 `--max-old-space-size=3072` 的 tsserver 进程）。
