# 嘴替鸭小程序 · 生产部署指南

本指南覆盖把 `zitiya-miniapp` 推上生产环境的三块独立组件：微信小程序主体、H5 版本、微信云函数。
管理后台（`admin/`，你本地 8787 跑的那个）的生产部署不在此文档范围，另行处理。

---

## 一、前置准备（一次性）

| 项目 | 获取位置 | 用途 |
|---|---|---|
| 小程序 AppID | 已在 `project.config.json`：`wx17195c3a70827174` | 上传标识 |
| 上传私钥 `.key` | 微信公众平台 → 开发管理 → 开发设置 → 代码上传 → 下载上传密钥 | `miniprogram-ci` 免开发者工具上传 |
| 云开发环境 envId | 微信开发者工具 → 云开发 → 环境设置 | 云函数 / 云数据库 / 静态托管 |
| CloudBase API 密钥 | 腾讯云控制台 → 访问管理 → API 密钥（SecretId / SecretKey） | CI 里 `tcb` 登录（本地用 `tcb login` 浏览器授权即可）|

> 上传私钥 `.key` 视同密码，**不要入库**。本地放 `scripts/private.key` 并加进 `.gitignore`；CI 里用 base64 存到仓库 Secrets。
> 微信公众平台建议给上传密钥配置 IP 白名单，避免密钥泄露后被滥用。

## 二、微信小程序（weapp）生产发布

构建产物目录由 `project.config.json` 的 `miniprogramRoot: "dist/"` 决定，`build:weapp` 输出到 `dist/`。

```bash
# 1. 安装依赖 + 构建生产包
npm install
npm run build:weapp        # 产物 → dist/

# 2. 上传（脚本见 scripts/upload-miniprogram.sh）
APPID=wx17195c3a70827174 \
KEY_PATH=./private.key \
VERSION=1.0.0 \
DESC="首次生产发布" \
./scripts/upload-miniprogram.sh
```

上传后**仍需人工在微信后台走完发布链路**：
微信公众平台 → 管理 → 版本管理 → 体验版预览 → 提交审核 → 发布。
微信不允许纯自动发布到线上，审核这一步绕不开。

> `--r`（robot）是 CI 机器人编号 1–30，多人/多流水线别撞号，否则上传互相冲突。

## 三、H5 版本生产发布

```bash
npm run build:h5          # 产物 → dist/（H5 模式输出的是网页）
```

部署静态资源三选一：
- **A. 微信云开发静态托管**（与小程序同环境，最简单）：
  `tcb hosting deploy dist -e <envId>`
- **B. 对象存储 + CDN**：腾讯云 COS / 阿里 OSS，配 CDN 域名。
- **C. 自有服务器**：nginx 托管 `dist/` 目录。

若 H5 要在微信内打开，需到微信公众平台 → 开发设置 → 业务域名，把托管域名加进白名单。

## 四、云函数部署

两个函数 `daily_crawler` / `get_daily_quotes` 都 `require('wx-server-sdk')`。
已为两者补了 `package.json`（含 `wx-server-sdk`），部署时用 `--install-dependency true` 在云端安装依赖即可，无需本地 `npm install`。

```bash
# 脚本见 scripts/deploy-cloudfunctions.sh
ENV_ID=<你的云开发环境ID> ./scripts/deploy-cloudfunctions.sh
```

单函数手动部署等价于：
```bash
tcb fn deploy daily_crawler \
  -e <envId> --dir cloudfunctions/daily_crawler \
  --install-dependency true --yes
```

要点：
- `daily_crawler` 带定时触发器（每天 01:00，见函数内注释），部署后到云开发控制台确认触发器已生效。
- 也可用微信开发者工具：右键 `cloudfunctions/daily_crawler` → 上传并部署（云端安装依赖）。
- 也可用 `miniprogram-ci` 的 `cloudFunctionDeploy`（同一套上传密钥，无需 `tcb` 登录），二选一即可。

## 五、配置同步（最容易漏的一步）

小程序运行依赖云数据库 `scene_config._id=main`，里面存 `crawlTopics` / `keywordOverrides` /
`dailyQuoteTTLDays` / `dailyQuoteLimit` 等。新环境部署后**必须**把这份配置写进云库，否则：

- 小程序退回代码里的硬编码默认值；
- 管理后台（admin）改的配置**不生效**（后台改的是本地 `admin/data/scene_config.json`，要靠「导入/导出 → 云数据库文档」同步到云库）。

同步方式：
1. 打开管理后台（`admin/`，`node server.js`）→ 导入/导出 → 导出「云数据库文档」；
2. 在云开发控制台 Database 里，把这份 JSON 写入集合 `scene_config`，`_id` 设为 `main`；
3. 或写个 `tcb db nosql execute` 脚本批量导入。

## 六、CI/CD 思路（GitHub Actions）

触发策略：打 `v*` tag 自动构建 + 上传 + 部署云函数（见 `.github/workflows/deploy.yml`）。

需要配置的仓库 Secrets：
- `WECHAT_APPID` = `wx17195c3a70827174`
- `WECHAT_UPLOAD_KEY` = 上传私钥 `.key` 的 **base64**（`base64 -i private.key` 生成）
- `TCB_ENV_ID` = 云开发环境 ID
- `TCB_API_KEY_ID` / `TCB_API_KEY` = 腾讯云 API 密钥

流水线：`checkout → setup-node → npm ci → build:weapp → 解码 key → miniprogram-ci upload → tcb login + fn deploy`。
审核与正式发布仍须人工在微信后台点（微信限制，CI 只能到「上传体验版」）。

## 附：Python 后端 `backend/`

仓库里还有 `backend/`（FastAPI 结构：`main.py` / `routers` / `crawler.py` / `scheduler.py`）。
当前小程序数据链路走的是**微信云函数 + 云数据库**，并未用到这个 Python 后端。
若生产要切换成 Python 后端，需另行用 `uvicorn` + 反向代理（nginx）单独部署，并与小程序端改连后端地址——不属于本流程。
